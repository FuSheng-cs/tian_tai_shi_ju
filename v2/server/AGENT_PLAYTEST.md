# Local independent-model playtest bridge

This harness lets an independent live Codex model agent play the character while the browser uses the real `NewAPI`, `Game`, `ModelNarrator.Generate` / `Finalize`, validators, request receipts, and durable store. It is not an external-provider connectivity test and it does not demonstrate a deployed model's token accounting or response latency. The character prose must be generated by the independent actor for the current request, never supplied from a response fixture or repaired by the player/tester.

The entire bridge is in `agent_playtest_test.go`: it cannot enter a normal shipping binary. It replaces only the narrator's DNS lookup and HTTP transport after constructing the real narrator. The adapter never performs network I/O, never reads real model credentials, and does not change production HTTPS/private-address checks. The production 45-second model timeout remains active.

## Run locally

From `v2/server`, in PowerShell:

```powershell
$env:V2_AGENT_PLAYTEST = '1'
$env:V2_AGENT_PLAYTEST_DIR = (Join-Path (Resolve-Path ../.run) 'agent-playtest')
$env:V2_AGENT_PLAYTEST_MINUTES = '120'
go test -run '^TestAgentPlaytestServer$' -count=1 -timeout 0 -v
```

`V2_AGENT_PLAYTEST_DIR` is optional and defaults to `v2/.run/agent-playtest`. Any override must name a child directory of the ignored `v2/.run`. The directory is restricted to mode 0700/0600 on Unix and the current user plus LocalSystem by inherited ACL on Windows. Existing `STOP` markers prevent reuse; choose a fresh child directory for the next run. Lifetime defaults to 120 minutes and accepts 1–240 minutes.

The listener is fixed to `127.0.0.1:8083`. Port conflicts fail without modifying another process. Point a separate local Vite origin (for example port 5176) at this API, preserving Host and Origin. Do not redirect the ordinary rehearsal service on port 8082. `ready.json` describes readiness and explicitly records `networkProviderVerified: false`.

To stop gracefully, create an empty `STOP` file in the run directory. The bridge waits up to 55 seconds for in-flight requests, writes `stopped.json`, and exits. The ordinary shipping service and main domain are never involved.

## Actor queue contract

Start the actor waiting before the player sends a line. Poll every 75–250 ms; the actor has less than 45 seconds from request publication to completion. Each generated job ID is independent of session capability IDs.

Keep deadline parsing timezone-aware. `deadlineAt` is an ISO-8601 UTC string ending in `Z`; Node `JSON.parse` followed by `Date.parse(summary.deadlineAt)` preserves this correctly. PowerShell may automatically turn JSON timestamps into DateTime values: reparsing the resulting localized string as a DateTimeOffset can miss an active request. One actual playtest retry exposed this watcher issue; it was not a character-model refusal. Keep each actor polling tool call bounded, and check the raw UTC deadline before generating a response.

- `queue/<job>.request.json` is the exact outgoing Chat Completions request body, including `model`, the two role-labelled `messages`, temperature, max_tokens, and response_format. No HTTP headers or credentials are written.
- `queue/<job>.summary.json` contains only safe job/trace IDs, kind (`turn` or `ending`), turn/phase or ending choice, timestamps, relative request/response filenames, and the request SHA-256. The summary is published after the full request is ready. It contains no player line, transcript, session ID, or credential.
- The actor reads the complete request body, follows `messages[0].content` as the character constraints, and treats the JSON inside `messages[1].content` as the scene data. Do not change the request to fit a planned story. The actor should read only the supplied transcript, not the player's future test plan.
- The actor writes **only** raw UTF-8 character JSON to `responses/<job>.response.json`: `{ "reply", "narration", "memory" }` for a turn, or `{ "reply", "narration" }` for a finale. No Markdown fences, prose wrapper, or completion envelope. Write a temporary sibling file, then rename it atomically to the final response filename; do not expose a partial file.
- Do not answer jobs that already have a `.result.json` file or whose `deadlineAt` has passed. A timeout is a failed attempt. A new retry gets a new job ID; preserve the old request and response for review.
- The adapter wraps the exact response bytes as a Chat Completion and returns them to production parsing. It does not strip fences, shorten text, repair JSON, or ground a memory on behalf of the actor. Invalid content must fail normally and consume no turn.

Queue files contain the test dialogue and are private test evidence, not application logs. Do not paste whole queue bodies, raw sessions, browser storage, or trace artifacts into public reports. Console output contains only local readiness and ordinary test status.

## Review chain

Each API response has an `X-Local-Playtest-Trace` header containing a newly generated trace ID. It never contains the session capability.

1. The HTTP trace ID links the browser response to `traces/<trace>.json`.
2. The trace links to the transport job, operation, HTTP status, timestamps, and actual API response snapshot with the top-level session `id` removed. A successful snapshot shows the real stored messages/revision; a rejected snapshot shows the real public error. The trace stores no request URL or browser command body.
3. The job summary records the exact request SHA-256. `queue/<job>.result.json` records timeout/cancellation or delivery to the production validator, response SHA-256 and byte count. **Delivered** does not mean **accepted**: the linked HTTP trace determines acceptance.
4. Preserve rejected, timed-out and successful attempts. Do not overwrite previous actor replies to make the playthrough pass. Durable idempotent retries can have a trace with no new model job; this is expected and demonstrates that the actor was not called twice.
5. Review the accepted redacted transcript against the raw actor output and the preceding exact request. Evaluate specificity, continuity, consent, callbacks, crisis boundaries, and whether the next player action made sense. Report human/agent elapsed handling time separately from provider latency; the queue bridge is not an inference benchmark.

The ordinary test suite checks byte preservation, cancellation evidence, and capability redaction. These deterministic checks do not stand in for live actor playthroughs.
