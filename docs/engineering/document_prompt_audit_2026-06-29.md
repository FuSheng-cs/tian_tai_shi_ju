# 《天台十句》文档与后端 Prompt 一致性审查

> 审查日期：2026-06-29  
> 审查对象：产品文档、投稿文档、技术文档、后端 Prompt、前端游戏契约与状态机  
> 结论口径：以当前可执行代码为事实源；历史建议文档只用于追溯，不视为现行规格。

## 一、结论摘要

当前世界观主轴基本一致：艾是独立摄影师，核心矛盾是“长期看见别人，却很少被真正看见”；玩家最多只能让她今晚暂时离开栏杆，不能治愈她；基础规则为 10 次机会、触动后返还机会、三种结局和相识后的后日谈。

但文档与实现尚未形成同一版本，存在 3 个高优先级问题：

1. `buildMainSystemPrompt()` 中同时保留了新旧两版 Prompt，首个 `return` 使旧版长 Prompt 成为不可达代码；现有 Prompt 文档却完整记录了不可达的旧版。
2. 当前主对话已经是“自然回复生成 + 独立规则裁判”的双调用架构，但 Prompt 文档和技术文档仍按“角色直接输出机制标签”的旧架构描述。
3. 角色身世、当晚触发事件、心理锚点和成功结局的关键语义条件没有进入当前生效的主 Prompt 或裁判硬规则，因而文档中的核心设定并不能稳定约束模型。

此外还有玩家是否认识艾、压力扣减、轻生题材表达边界、Provider 清单和测试现状等口径差异。详情如下。

## 二、当前真实运行链路

主线每个回合实际进行两次模型调用：

1. `buildMainSystemPrompt()` 生成角色 Prompt，模型只返回艾的自然回复，温度 `0.8`。
2. `buildTurnEvaluationSystemPrompt()` 作为独立规则裁判，读取历史、玩家本句和艾的回复，返回结构化 JSON，温度 `0.2`。
3. 后端将裁判结果作为 `evaluation` 返回前端。
4. 前端根据 `affectionDelta`、`pressureDelta`、`aiState`、`emotion` 和 `endingType` 更新游戏状态；回合归零时再执行本地兜底结局判定。

当前实际存在 5 类 Prompt，而不是 4 类：

| Prompt | 实际职责 | 温度 |
| --- | --- | ---: |
| 主线角色生成 | 只生成艾的自然回复 | 0.8 |
| 回合规则裁判 | 输出情绪、状态、好感、压力和结局 JSON | 0.2 |
| 提示 | 输出 20 字以内的方向性提示 | 0.7 |
| 后日谈 | 生成相识后的日常聊天，并承接本局上下文 | 0.7 |
| 局后摘要 | 生成关键转折句和短评；死亡结局前端使用本地摘要 | 0.35 |

投稿文档 `docs/submission/award_optimized_submission.md` 第 200—212 行已经正确描述了双层架构，是现有文档中最接近当前实现的一份。

## 三、问题清单

### P0-1：生效 Prompt 与文档记录的 Prompt 不是同一份

**证据**

- `backend/llm/service.go:568-595` 的 `buildMainSystemPrompt()` 在第一个 `return fmt.Sprintf(...)` 处已经结束。
- 同一函数 `backend/llm/service.go:597-710` 还保留一份完整的旧 Prompt，但它永远不会执行。
- `docs/engineering/prompts_and_settings.md:14-101` 记录的正是这份不可达旧 Prompt，并声称它“实际参与 LLM 调用”。
- 后端测试 `TestBuildMainSystemPromptDoesNotAskForMechanicTags` 明确要求生效主 Prompt 不得包含机制标签，进一步证明文档采用了旧口径。

**影响**

- 文档声称已注入的身世、触发事件、心理锚点、好感阶段、压力阶段和标签规则，实际上没有进入角色生成调用。
- 开发者修改旧长 Prompt 不会改变线上行为，极易产生“改了 Prompt 但体验没变化”的误判。

**建议**

- 删除不可达旧 Prompt，或明确选择其中一版重构为唯一实现。
- 自动从代码或版本化 Prompt 模板生成 Prompt 文档，避免再次复制漂移。

### P0-2：技术文档仍描述旧版“正文标签解析”架构

**证据**

- `docs/engineering/prompts_and_settings.md:9` 称主线模型生成回复、情绪标签、好感标签和结局标签。
- `docs/engineering/technical_overview.md:61-95` 称前端解析 `[好感度+5]`、状态、情绪和结局标签。
- 当前 `llm.Chat()` 会先用 `stripKnownMechanicTags()` 清理角色回复，再调用 `EvaluateTurn()`；前端 `gameStore.sendMessage()` 直接消费结构化 `evaluation`。

**影响**

- API 契约、故障排查和测试策略都会被旧文档误导。
- 文档漏掉第二次模型调用，导致成本与延迟估算偏低。

**建议**

- 将 Prompt 文档改成 5 类 Prompt，并补充裁判 JSON schema。
- 将技术流程改成“双调用 + 结构化响应 + 前端兜底结局”，把标签解析标为兼容旧返回的遗留能力。

### P1-1：核心角色设定没有约束当前生效的角色模型

**证据**

当前生效主 Prompt 只稳定提供：

- 艾是独立摄影师；
- 她长期替别人看见痛苦，却很少被看见；
- 她疲惫、敏感、防备；
- 玩家只能让她今晚暂时离开栏杆。

以下文档正典没有进入生效 Prompt：

- 20 岁出头、紫色内染发；
- 福利机构与临时寄养经历；
- 作品被称为“漂亮的痛苦”并被当成展览噱头的当晚事件；
- 旧相机、未冲洗照片、冷饭团等心理锚点；
- 生活化说话方式与更细的禁区。

这些内容只存在于不可达旧 Prompt、产品文档和提示 Prompt 的部分摘要中。

**影响**

- 不同 Provider 容易补写互相冲突的身世、动机和语言风格。
- 提示系统可能建议玩家谈照片，但角色生成层不一定知道照片背后的具体事件。

**建议**

- 将本次新增的设定集压缩成一段“不可变角色事实”，同时注入角色生成与规则裁判。
- 不要把完整设定集逐字塞进每次调用；应维护一个精简、版本化的 Prompt 投影。

### P1-2：“相识”结局的核心语义条件没有被硬性执行

**文档口径**

`storyline_and_lore.md` 和旧 Prompt 都要求玩家真正点破“她一直看见别人，却没人看见她”的核心矛盾，才允许触发相识。

**实现口径**

- 后端 `normalizeEvaluationEndingType()` 只校验：好感 `>=25`、好感触发 `>=5`、玩家发言 `>=7`。
- 前端 `resolveFallbackEndingType()` 也只校验同样三个量化条件。
- 当前裁判 Prompt 没有把“点破被看见悖论”定义为 `end_acquaintance` 的必要条件。

**影响**

玩家可以通过 5 次普通但符合加分标准的共情表达达到相识，不必触达文档声明的核心主题。反过来，模型也可能因文字动作与阈值不一致而拒绝一个叙事上合理的相识结局。

**建议**

- 在裁判结果中增加可验证维度，例如 `core_conflict_seen: true/false`，并把它纳入相识结局硬门槛。
- 或明确修改产品文档，承认当前相识只由量化阈值决定。两种口径必须二选一。

### P1-3：“十句话”文案遗漏压力额外扣减

**证据**

- 玩家每发言一次，前端先扣 1 次机会。
- 裁判返回 `pressureDelta=1` 或 `2` 时，前端还会额外扣 1 或 2 次机会。
- 裁判定义：说教或轻度冒犯为 1；辱骂、威胁、调情物化、鼓励坠落或明确放弃为 2。
- 触发好感 `+5` 时返还 1 次机会。

**差异**

玩家指南只写“开局 10 次发言机会”和“触动后获得额外回合”，没有说明一句伤害性表达可能消耗 2—3 格机会。因此玩家并不总能实际说满 10 句。

**建议**

- 对外统一表述为“初始 10 格开口机会”；普通发言消耗 1 格，伤害性表达会额外消耗，真正触动会返还 1 格。
- 如果产品坚持宣传“你真的只有十句话”，则不应让压力直接扣减同一回合资源，应改为独立压力轨道。

### P1-4：玩家与艾的初始关系互相冲突

**陌生人版本**

- `storyline_and_lore.md`：玩家是偶然走上天台的陌生人。
- `player_guide.md`：玩家对艾一无所知。
- 生效主 Prompt：艾正在和一个“刚走近你的人”说话。

**认识版本**

- `gameContract.ts` 开场第 3 帧：“是艾。”
- 初始旁白：“你记得她，那个在夜色中游荡的摄影师。”

**影响**

玩家能否一开始就谈她的摄影身份、名字和习惯，会直接改变合理台词范围，也影响“看见她”究竟来自观察还是既往了解。

**本次设定集决议**

采用“完全陌生”版本：玩家只从现场观察到相机、烟和危险姿态，不预先知道她的名字、职业与经历。现有开场两句应在后续实现修订。

### P1-5：伦理原则与部分宣传、结局文案冲突

**原则**

产品文档和 Prompt 多次要求不把轻生浪漫化、奇观化或攻略化，也不把玩家塑造成救世主。

**冲突用语**

- 玩家指南使用“危险、迷人”形容核心氛围。
- 故事线称死亡结局为“宿命的坠落”。
- 玩家设定写“被她的危险状态和气质吸引”。
- 坠落演出部分文字使用诗化、唯美化描写，弱化了死亡后果。

**建议**

- 用“压迫、脆弱、迫近”替换“迷人”“宿命”等表达。
- 避免把危险姿态作为吸引力来源，避免详细、唯美化呈现坠落过程。
- 在入口加入内容提示、虚构声明和“不能替代现实危机干预”的边界说明；现实危险情境应引导联系当地紧急服务或可信赖的人。

### P2-1：局后摘要和后日谈文档落后于实现

**差异**

- 当前局后摘要 Prompt 已增加三种结局的专用评语限制，文档未记录。
- 死亡结局不调用摘要模型，而是直接使用前端本地摘要；文档没有说明。
- 当前后日谈 Prompt 会注入真实结局、关键句、最后一句、结局回复、短评、使用句数和好感等上下文；文档仍只记录固定基础 Prompt。

**建议**

补齐实际 payload、分支策略和上下文截断规则，避免误判后日谈为无记忆的独立聊天。

### P2-2：Provider 默认配置表不完整

`prompts_and_settings.md` 只列出 OpenAI、Qwen 和 Doubao。后端当前还支持 DeepSeek、Kimi、智谱，以及 Claude/Anthropic 原生 Messages API。前端 Provider 列表也包含这些选项。

### P2-3：技术现状文档包含已失效信息

- `technical_overview.md` 仍声称存在 `next_temp/`，当前仓库中没有该目录。
- 文档记录“2 个测试文件、4 个测试用例”，投稿文档记录“9 个测试文件、61 个测试”。本次实测前端为 10 个测试文件、80 个测试全部通过，两个旧数字均已失效；后端 `go test ./...` 也通过。
- `prompt_gameplay_optimization_suggestions.md` 描述的“角色与裁判未分层”已经完成，不应继续标为当前问题；它应移动到归档或标注适用版本。
- `optimization_report.md` 和 `optimization_requirements.md` 是 4 月份审查快照，其中多项问题已修复，不能作为 6 月当前状态说明。

### P2-4：AI 结局判定的对外表述略有夸大

AI 裁判确实可以返回结局，但当机会归零而裁判没有返回结局时，最终结果由前端 `resolveFallbackEndingType()` 按阈值确定。因此更准确的表述是：

> AI 参与逐回合情绪、关系、压力与结局判断；前端规则层负责校验阈值，并在机会耗尽时执行确定性兜底结算。

## 四、已核对一致的内容

- 游戏名：天台十句。
- 角色名：艾。
- 初始机会：10。
- 单次好感增量：5，并返还 1 次机会。
- 初始提示次数：3。
- 情绪类型：刺痛、惊讶、柔软、好奇、无明显波动。
- 持续状态：戒备、观察、动摇、回身、临界。
- 结局：死亡、消失、相识。
- 消失量化门槛：好感至少 20、触发至少 4 次、发言至少 7 次。
- 相识量化门槛：好感至少 25、触发至少 5 次、发言至少 7 次。
- 只有相识结局提供“添加联系人”入口。
- 后日谈保持艾尚未被治愈、仍疲惫敏感的状态。
- 当前不是真流式输出；打字机效果发生在完整响应到达之后，流式属于未来方向。

## 五、建议修复顺序

1. 先清理 `buildMainSystemPrompt()` 的不可达旧 Prompt，确认唯一生效版本。
2. 把设定集的精简角色事实注入主线角色层，并把结局语义条件注入裁判层。
3. 重写 `prompts_and_settings.md` 和 `technical_overview.md` 的双调用流程。
4. 统一玩家是否认识艾；本设定集已选择“陌生人”版本。
5. 明示压力扣减规则，或将压力改成独立资源。
6. 收敛轻生题材的宣传和结局措辞，补充内容与现实危机边界。
7. 更新 Provider、后日谈、摘要和测试现状，将过期建议文档标记为历史快照。

## 六、建议的事实源优先级

后续维护建议采用以下顺序：

1. `docs/product/game_setting_bible.md`：世界观、人物、叙事和伦理正典。
2. `backend/llm/game_contract.go` 与 `legacy_vue/src/domain/gameContract.ts`：可执行枚举、ID、阈值和资源契约。
3. 后端 Prompt 模板：设定集与规则契约的运行时投影。
4. 玩家指南、项目介绍、投稿稿件：从上述事实源派生的对外表达。
5. 优化报告与历史建议：只保留日期和版本语境，不作为当前事实源。
