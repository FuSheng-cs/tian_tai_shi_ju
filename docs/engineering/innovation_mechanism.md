# 创新论证｜自由语言怎样成为游戏规则

> 2026-10-29 · AIC。本文区分实现事实、设计理由与待验证效果，不宣称行业首创。

## 创作命题与技术命题

创作命题是：面对困境中的人，仔细斟酌说出的每一句话。技术命题是：怎样让玩家自己组织的语言进入可反馈、可结算、有终点的游戏规则？

本作以“自由输入 → 角色回应 → 结构化语义判定 → 程序结算 → 可感知反馈”共同回答这两个问题。语言是玩家操作，十句是资源约束，状态是反馈，结局是收束。删去其中任何一环，都会改变玩家为什么停下来想下一句。

## 机制与表达相互证明

| 设计 | 游戏中的作用 | 对创作命题的贡献 | 实现依据与限制 |
| --- | --- | --- | --- |
| 自由语言输入 | 玩家自己组织话语，输入随上下文变化 | 让开口成为自己的选择 | GameView.vue、gameStore.ts；无法保证任意输入都被正确理解 |
| 最多十句话 | 每次发送消耗一次机会，信任不返还句数 | 让玩家衡量当下最值得说什么 | gameContract.ts、game_contract.go、gameStore.ts |
| 角色与独立裁判 | 角色生成自然对白，裁判返回结构化状态 | 让回应的含义进入反馈，而非只得到另一段文字 | service.go 的 Chat / EvaluateTurn；两次顺序调用，错误可能相互影响 |
| 程序守门 | 归一化字段、结算信任、校验结局条件 | 维持十句与结局边界，使互动能够收束 | 前后端契约和低信任拦截；程序边界可确定，语义判断仍不确定 |
| 对白、状态与预制 CG | 呈现戒备、动摇、落泪、离开等变化 | 让玩家观察回应，再决定下一句 | gameContract.ts、GameView.vue；画面由状态选择，不是实时生图 |
| 后日谈 | 安全离开后延续上下文 | 让人物生活延续，避免把一次对话当作全部 | ChatAfterStoryView.vue、SaveSystem.ts、路由守卫 |

以上源码位于 `legacy_vue/src/` 与 `backend/llm/`，详见[技术说明](technical_overview.md)。

## 一轮交互的实际顺序

1. 前端记录本句并消耗 1 次机会，发送历史、剩余机会、信任与状态。
2. 后端角色调用生成艾的自然对白。
3. 独立裁判结合本句、历史、角色回复与当前状态输出 `emotion`、`ai_state`、`trust_delta`、`pressure_delta`、`ending_type`、`confidence`。
4. 程序校验结构和枚举，先扣压力造成的信任损耗，再加信任增量，上限 15。
5. 安全离开同时要求本轮结算信任达到 15 和有效叙事判定；低信任离开会被拦截。满分或哭泣不自动成功。
6. 前端显示对白、机会和状态对应画面；十句耗尽且没有有效安全结局时，保守收束为拒绝离开。

裁判判断的是上下文中的表达，不是给现实中的人做心理测量。双调用采用职责拆分，不能称为两个模型独立验证真相；它们可使用同一服务商或模型。

## 从模型条件反推游戏形态

- **交互规模与成本**：十句约束单局主线回合数，使预算更可估计；提示、摘要、后日谈与重试仍有额外调用，历史长度也影响 token。没有测量不能写“节省多少成本”。
- **响应延迟与节奏**：单场景、短对白和等待表现为沉默、观察留出节奏空间。它们缓和等待的感受，不能消除网络延迟；双调用还可能增加延迟。
- **发散与不稳定**：固定天台、人物设定、短回复要求、结构化裁判和程序门槛限制叙事跳跃。字段归一化不等于理解永远准确。
- **数字媒体呈现**：CG、对白节奏、机会刻度与后日谈让状态变化可以被看见。当前打字机在完整响应到达后本地播放，不能当作网络流式证据。

## 怎样证明创新确实落地

展示时应把一条实际输入、角色实际回复、裁判 JSON、程序结算和界面变化放在同一条证据链上。低信任拦截结局可用对应测试解释程序边界。Mock 证明契约与程序行为，真实模型记录用于观察语义与体验，二者分列。

可复核位置：`legacy_vue/tests/gameStore.test.ts`、`legacy_vue/tests/gameContract.test.ts`、`backend/llm/trust_gate_test.go`、`backend/llm/game_contract_test.go`。未重新运行时只能标为代码或历史记录，不引用旧测试数量作为本轮结果。

## 效果边界

本作探索的是一种让表达具有游戏后果的交互结构。玩家是否更愿意斟酌、能否把这种注意带到现实，尚需用户研究；不能从代码或通关结果推导心理干预成效。作品希望玩家留意困境中的人、思考具体回应，效果应通过真实体验与反馈继续验证。
