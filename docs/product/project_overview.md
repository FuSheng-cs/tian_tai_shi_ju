# 《天台十句》项目概述

> 2026-10-21 · shumei-merge 数媒版。玩法事实以代码契约为准，叙事正典见[游戏设定集](game_setting_bible.md)。

## 一句话介绍

《天台十句》是一款以 AI 原生交互为核心玩法的短篇叙事游戏：面对困境中的大学生艾，玩家只有十句话，需要自己组织每一次回应；AI 将自由语言转化为信任、情绪、姿态与结局判断，程序把这些判断落实为游戏反馈。

## 创作命题：只有十句话，你会怎样开口？

我们想让玩家关注那些已经很难开口的人，并在相遇时认真思考如何具体回应。核心体验是斟酌：这句话回应了她刚才说的什么？是否急着替她下结论？是否留下了继续表达的空间？玩家输入的每句话都要付出一次机会，无法用无限输出代替倾听。

这一命题适合通过游戏表达，因为玩家必须亲自开口、看到回应、调整下一句。紧张、犹豫、观察和试探构成玩法，立意由操作和后果产生。游戏没有预设一套人人适用的十句答案。

## 创作缘起与虚构改编

创作缘起来自创作者身边同学转述的一段真实经历：一位实习老师曾流露自己承受的压力，后来去世。回望这段经历，创作者关注的是：当一个人试着开口时，我们是否意识到应当停下来，认真听一听，并想清楚怎样回应。

公开材料匿名处理，不补写学校、考核、家庭、诊断或准确时间线，不把某一句安慰归因为死亡原因，也不归责当时的听者。艾是虚构大学生，其具体压力、天台场景和对白属于创作，并非对逝者经历的还原。详细口径见[来源说明](../submission/source_notes.md)。

## 具体的人与具体的互动

艾承受着学业压力、网络嘲讽、家人的期待和长期孤独。这些内容通过对话逐渐浮现，玩家面对的首先是一个疲惫、戒备的人。当她说“说了也没人听”，下一句能否接住她刚才的表达，便成为玩家自己的问题。

“手机里输入求助又删除”的镜头是答辩演示的虚构设想，用于呈现开口的困难；在没有代码或素材依据时，不能称为现有游戏开场 CG，也不能称为真实聊天记录。

## 从语言到规则的闭环

1. 玩家自由输入，本局最多十次有效发送，每次消耗一次机会。
2. 角色模型结合上下文生成艾的自然回复。
3. 独立 JSON 裁判结合本句、回复和状态，判断信任变化、压力、情绪、姿态和结局。
4. 前后端程序校验字段与门槛，结算状态；信任增加不返还机会，压力不额外扣机会。
5. 对白、角色画面、剩余机会和结局把后果反馈给玩家，影响下一次表达。

创新的完整论证及实现位置见[AI 原生机制论证](../engineering/innovation_mechanism.md)。

## 当前版本与完成边界

- 大学生艾、固定十句上限、信任 0—15、初始提示 3 次。
- 两个结局：安全离开 / 拒绝离开。安全离开须本轮结算信任达到 15，且 AI 判定叙事条件成立；满分不自动成功。
- 安全离开使用预制的“落泪—抹泪—一起进入楼梯间”三段 CG，之后可进入后日谈；拒绝离开止于仍在天台的沉默。
- 保留本地三栏位存档、成就、提示及结局摘要；主线为角色与裁判两次顺序模型调用。
- 打字机是本地显示效果；未实现网络流式、实时生图、多模态上传、电话、碎片与循环系统。

十句限制约束单局交互规模，不能直接证明成本降低比例或绝对 token 上限；双调用也会增加开销和延迟。固定场景、短对白、结构化裁判和程序守门共同约束发散，但无法保证模型理解永远正确。

## 希望玩家带走什么

游戏希望留下的是一种具体的停顿：遇到难以开口的人，先留意对方说了什么，再决定自己说什么。认真回应前文、询问对方此刻需要什么、商量眼前可以一起做的小事，都可以成为思考方向，不能当作必胜话术。

“只有十句话”是游戏规则，现实支持没有十句期限。结局与分数不代表现实处置能力。艾走进楼梯间也只是故事的一步；后日谈让一次相遇继续展开。作品的表达落在玩家如何开口，以及游戏结束后会怎样对待身边欲言又止的人。
