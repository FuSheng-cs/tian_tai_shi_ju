## 已拍板决策（2026-07-26，项目所有者确认）

1. **技术路线**：继续 Web 栈演进。前端在 `legacy_vue`（Vue 3 + TS + Pinia + Tailwind）基础上迭代，后端沿用 Go + Gin；像素美术 + 视差 + 粒子/光效模拟《Tokyo Stories》式 2.5D 氛围，不引入游戏引擎。
2. **交付方式**：先完成全案文档 + 艾章 Demo 蓝本，代码实现按里程碑另行开工。
3. **苏晚与林默的关系**：夜间挽留员搭档（挚友，情感暧昧留白，不写成明恋人）。
4. **艾的人设**：融合版——保留「独立摄影师 · 被看见悖论」的身份与表层矛盾，新增「缪斯芯片将她的记忆压缩殆尽」作为深层真实创伤。拍照 = 把记忆存在芯片外的自救；她快忘了自己为什么拍照。旧版美术、剧本、Prompt 资产尽量复用。

## 设计基线（所有分册必须一致引用）

### 命名

- 游戏名：《天台十句》（沿用）
- 主角：**林默**（默）——前忆枢科技「夜间挽留员 / Retention Agent」
- 搭档：**苏晚**（晚）——同为挽留员，当年真正坠落的人
- 公司：**忆枢科技 / MnemoCore**
- 芯片：**缪斯 / Muse**（神经耦合芯片）
- 协议：**最后协议**（最终决定前只分配十句对话额度）

### 句数经济（数值基线）

- 基础额度：每位 NPC **10 句**；视觉呈现为一根烟，烧完即清空。
- 语言真正触动对方（好感事件）：**+1 句**。
- 出示高相关记忆碎片并命中情绪锚点：**+2 句**。
- 出示无关 / 错误碎片：**-1 句**，并触发审查协议或记忆幻觉演出。
- 同一枚碎片对同一 NPC 每周目只能出示一次。

### 碎片与循环

- 主线关键碎片 **6 枚**（艾→周伯→童→夏→镜→苏晚，闭环回到林默），另有支线碎片若干。
- 周目间碎片继承上限 **3 枚**（背包 = 外置上下文窗口）。
- 无论成败，每夜结束后回滚到当晚开始；周目号递增；跨周目记忆以「有损摘要」呈现。

### NPC 链（哀伤阶段映射，沿用 Notion 定稿）

艾（否认·教学）→ 周伯（愤怒）→ 童（讨价还价）→ 夏（抑郁/愧疚）→ 镜（解离·真伪高潮）→ 苏晚（直面真相）→ 终章·林默（接受）。

### 打火机闭环（搭档版）

刻着「给晚」的打火机是林默送苏晚的搭档信物——挽留员的传统：替对方点一支烟，就是多为一个人争取一句话。苏晚坠落后，林默把它转赠给艾（他作为挽留员救下的第一个人）。玩家在序章从艾手中看到它，在苏晚章揭晓来历。

### 终章反转

一直操控「你」的，是林默芯片里耦合的 AI 挽留员——苏晚坠落后，林默为了不让自己也跳下去，亲手写进芯片的。质子视角（第三人称抽离），打破第四面墙。终章 BGM：Im Sog der Feuer des Schicksals。

### 技术基线

- 碎片相关性判定：embedding 余弦相似度，双阈值三档（命中 / 中性 / 错误）；无 embedding 服务时降级为 LLM 判定器。
- 温度 = 精神状态：由后端按 NPC 状态标签映射采样温度（权威映射表唯一存放在 04 册 4.1，02/03/05 册引用不另列数值）。
- 延迟处理优先级：流式输出 + 零延迟占位反应 + 人设化思考动作三者叠加；快慢双模型为进阶项，Demo 阶段不做。
- 内容审查协议、提示词泄露均为**预写受控内容**，不依赖模型真实越狱/泄露。

### 体验目标

- 单周目（一夜）：30–45 分钟（艾章教学关特例：15–25 分钟，与「完整通关 2–3 小时」的总量咬合）；完整通关（含终章）：2–3 小时。
- 平台：桌面浏览器优先，移动端适配保留。
- 唯一动词是「说话」：没有战斗，语言是唯一的武器。

### 术语表

| 术语 | 含义 |
| --- | --- |
| 句数 / 烟 | 对话额度，最后协议分配的上下文预算 |
| 记忆碎片 | 可收集、可出示的信息物件（照片、录音、工牌等），玩法化 RAG |
| 出示 | 在对话中把碎片注入 NPC 上下文的动作 |
| 情绪锚点 | NPC 当前创伤/情绪的语义锚文本，用于碎片相关性判定 |
| 审查协议 | 缪斯芯片的对齐层，触发时 NPC 打官腔、回避 |
| 私密钥词 | 让 NPC 卸下审查防备的个人化钥匙信息 |
| 模型化 | 记忆压缩副作用：人说话变模板、情感变采样 |
| 回滚 / 周目 | 芯片快照回档；一夜为一个周目 |
| 有损摘要 | 跨周目记忆的失真压缩呈现 |
| 挽留员 | 忆枢雇佣的高共情劝说者，「由人来运行的劝说 Agent」 |
| 质子视角 | 终章抽离出的第三人称俯视视角 |

## 与 v1 的关系

v2 计划继承并升级 v1 的十句机制、好感反馈、打字机与等待演出；艾章是 v1 的世界观化重构（序章/教学关）。当前代码基线已采用“自然回复 + 独立 JSON 裁判”，旧正文标签只用于兼容清洗，不应恢复为新机制事实源。v2 目标是以「每夜结局 + 全局真结局」替换 v1 三结局，细节见 02 册；本次只提交设计，尚未实现该替换，也未核实线上部署版本。
