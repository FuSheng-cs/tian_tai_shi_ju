# V2 独立发布手册

## 保护边界

运营版 `tiantaishiju.top` 只读。禁止覆盖其目录、环境变量、数据库、进程、服务定义或虚拟主机。
未经确认，不对共享 Nginx、Docker 编排或宿主机服务执行重启/重载。

当前代码在 `v2/` 内：前端 `web/`、服务端 `server/`，独立端口 `8082`，没有依赖 v1 API。
部署示例采用 `/srv/tiantai-v2`、`tiantai-v2.service`、`/var/lib/tiantai-v2`。
这些是**建议路径，不代表已发现服务器实际布局**。

## 发布前只读确认

连接服务器后先检查 v2 实际工作目录、服务名、端口占用、反向代理、证书路径与持久卷。
确认 `v2.tiantaishiju.top` 的请求不会落到 v1 进程；比对生产与 v2 的独立路径和用户。
不读取或输出密钥值。安全配置仅需确认名称与是否可用。

需要的接入信息是 SSH 主机、用户名、端口和已配置的认证方式；私钥和密码由安全凭据入口提供。
仅有域名不能推断 SSH 账户或服务目录。

## 构建与候选发布

1. 本地运行 `bash v2/scripts/build.sh` 和 `cd v2/web && npm run test:e2e`。
2. 将 `.run/tiantai-v2` 与 `web/dist/` 复制到一个**新的** v2 发布目录，例如 `/srv/tiantai-v2/releases/<commit>/`；静态产物放在其中 `web/`。
3. 在独立临时端口上使用全新 v2 数据目录启动候选后端，验证健康接口、排演完整流程、刷新恢复，以及真实模型流程。
4. 配置 v2 专用系统用户、服务文件和安全环境文件。参考 `v2/deploy/tiantai-v2.service`；密钥文件建议 root 拥有、0600。
5. 根据实际服务器管理方式切换**v2 自己**的发布指针与后端进程。参考 `nginx-v2.conf.example`，保留现有 v1 配置。
6. 在 v2 域名检查所有静态资源、同源 API、移动端和模型响应。检查主域名仍返回原版本，仅做只读验证。

Nginx 示例是独立主机配置模板，不是自动安装脚本。证书路径需要验证；共享 Nginx reload 只有在配置测试通过、确认不会影响生产时才可考虑。若能复用现有 v2 路由与端口，不需要重载代理。

## 存储和回滚

- 数据目录只由一个 v2 服务进程写入，不能多实例共享。横向扩容需要先迁移事务数据库。
- Session ID 是随机能力凭据，不写访问日志，不公开分享会话 URL；TLS 必须开启。
- API 位置的 access_log 与 error_log 均不能保存会话 URL；示例关闭这两项，故障观测使用不含请求路径的服务日志与健康检查。
- 如使用示例 Nginx，它会覆盖 `X-Real-IP`。后端只有在直连地址属于 `V2_TRUSTED_PROXY_CIDRS` 时才相信该字段；示例只信任本机回环地址，后端也只监听回环。不要信任任意来源或直接照搬不匹配的代理网段。
- 所有 API 禁止缓存，静态 `index.html` 不长缓存；只有带 hash 的 assets 可长期缓存。
- 首次替换旧的 PWA 前端时需核实该**v2 origin** 的 service worker；不可触及生产 origin 的 worker 或存档。
- 发布前记录 v2 的旧发布路径和服务设置。回滚只恢复 v2 指针并重启 v2 进程，保留新旧存档以备排查。
- 未验证兼容性时不得让旧后端读取新的持久化记录。

## 当前验证边界

此手册与模板不意味着已连接服务器或部署。连接、真实模型验收和公网结果以实际执行记录为准。
